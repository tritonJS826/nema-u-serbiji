# agents.md — durable project knowledge

Статический каталог домашней еды и продавцов из Telegram-чата
**«Русскоговорящий Ниш Сербия»** (`https://t.me/rus_nis`).

Сайт: `index.html` + `app.js` + `styles.css` + `data/catalog.json`.
Сборки нет: это обычные статические файлы. Данные читаются через `fetch`,
поэтому открывать нужно по HTTP, а не через `file://`.

```bash
python3 -m http.server 8000
# http://localhost:8000
```

---

## 1. Источник данных и правило отсечки

- Экспорт: `ChatExport_2026-11-25/` (HTML-экспорт Telegram, 27 страниц,
  фотографии — в `photos/`: 2 119 полноразмерных JPG и превью; к сообщениям
  периода относятся 1 994 уникальных фото).
- Последнее сообщение экспорта: `2026-11-25 17:22:12`.
- Правило: берём только сообщения за **последние 365 дней** от самого нового
  сообщения экспорта. Для текущего экспорта это период
  `2025-11-25 17:22:12` — `2026-11-25 17:22:12`.
- Всё старше года **не участвует** в каталоге. Не добавлять товары и цены из
  старых сообщений, даже если они выглядят актуальными.
- `data/messages.jsonl` — 26 571 разобранное сообщение за этот период.
  Поля: `id`, `dt`, `author`, `text`, `links`, `media`, `photos`, `preview`,
  `reply_to`, `forwarded_from` (набор может расширяться парсером).
  `photos` — массив путей вида `photos/photo_…jpg` относительно папки
  экспорта (пустой массив, если фото нет).

### Пайплайн

```bash
# 1. HTML-экспорт -> JSONL с отсечкой по 365 дням
python3 tools/parse_export.py ChatExport_2026-11-25 data/messages.jsonl --days 365

# 2. Подсказка для ручной семантической курации (не часть сайта)
python3 tools/candidates.py data/messages.jsonl > data/candidates.txt
```

`tools/candidates.py` — вспомогательный инструмент: он лишь группирует
сообщения по авторам и ключевым словам. **Решение о создании карточки
принимается вручную** после чтения сообщений, а не по регулярке.

## 2. Что попадает в каталог

Включаем:

- частных продавцов домашней еды, выпечки, заготовок, полуфабрикатов,
  солений, рыбы, мёда и т.п.;
- небольшой домашний фастфуд/кулинарию, если это по сути домашняя еда
  («Гараж старог мајстора» — включён);
- продавцов, которые принимают заказы через личку, группу или сообщение в чате.

Не включаем:

- рестораны, кафе, доставку из заведений, магазины и сети;
- туристические услуги, аренду, перевозки, обсуждения «где купить»;
- сообщения «посоветуйте, где поесть» и прочие рекомендации без продавца;
- перепродажу магазинных товаров, если это не домашнее производство.

Один продавец = **один Telegram-контакт** (личный аккаунт, группа или канал).
Если у продавца нет публичного username, всё равно создаём продавца, но
контакт ведёт на его сообщение в общем чате (см. §5).

## 3. Схема `data/catalog.json`

```jsonc
{
  "updated_at": "2026-11-25",
  "source": { "chat_title": "...", "chat_url": "...", "export": "...",
              "period_from": "...", "period_to": "..." },
  "categories": [ { "id": "fish", "label": "Рыба и морепродукты", "emoji": "🐟" } ],
  "sellers": [ {
    "id": "radeco",                  // стабильный slug, используется в URL
    "name": "RADECO",
    "person": "Юлия Радулович",
    "emoji": "🥟",
    "color": "#f7eadf",              // фон плейсхолдера карточки
    "tg_kind": "group",              // user | group | message
    "tg_handle": "radeco_homefood",  // null, если username нет
    "tg_url": "https://t.me/radeco_homefood",
    "place": "Ниш · доставка партиями",
    "about": "...",
    "source_message_url": "https://t.me/rus_nis/190110",
    "updated_at": "2026-11-19"
  } ],
  "products": [ {
    "id": "radeco-dumplings",        // стабильный slug, используется в URL
    "seller_id": "radeco",
    "name": "Пельмени домашние",
    "category": "dumplings",         // id из categories
    "description": "...",
    "image": "data/images/products/radeco-dumplings.avif", // AVIF или null
    "price": 650,                    // число в RSD или null
    "unit": "кг",                    // за что цена
    "price_note": "10 шт — уточняйте",
    "price_unknown": false,
    "tags": ["пельмени", "заморозка"],
    "source_message_url": "https://t.me/rus_nis/190110",
    "updated_at": "2026-11-19"
  } ]
}
```

Правила:

- Валюта — **RSD / динары**. В тексте чата встречаются «дин» и «RSD»; в
  каталоге всегда число + `RSD`.
- `price` — цена за `unit`. Если цена «от» или зависит от веса, ставим
  минимальную/типовую и поясняем в `price_note`.
- Если цены нет вообще — `price: null`, `price_unknown: true` и
  `price_note: "цену уточняйте у продавца"`. На сайте такие товары получают
  отдельный заметный бейдж **«Цена не указана»** (жёлтый, со штриховкой).
  Не придумывать цену и не переносить её из другого продавца.
- `description` — короткое человеческое описание, не копия всего сообщения.
- `image` — путь к **AVIF**-фото товара относительно корня сайта
  (`data/images/products/<product-id>.avif`) или `null`/отсутствует, если
  подходящего фото нет. JPG/PNG в каталоге и на сайте не используем: исходные
  JPG из экспорта конвертируются в AVIF (см. §7).
- `tags` — слова для поиска: синонимы, состав, особенности.
- `source_message_url` — ссылка на сообщение, откуда взята карточка.
  Для сообщений общего чата: `https://t.me/rus_nis/<messageId>`, где
  `messageId` — число из HTML `id="message190467"` (то есть `190467`).
- `updated_at` — дата последнего сообщения, на котором основана карточка.

## 4. Уникальность и обновление без дублей

Ключ уникальности товара:

```
(seller_id, normalized(product.name))
```

`normalized` = нижний регистр, `ё → е`, схлопнутые пробелы, без эмодзи и
пунктуации по краям. Один и тот же товар у **разных** продавцов — это две
разные карточки (у каждого свой продавец и цена).

При повторном предложении того же товара у того же продавца:

1. не создавать новую карточку;
2. обновить `price`, `unit`, `price_note`, `description`, `updated_at`;
3. взять **самое свежее** сообщение (по `dt`) и его `source_message_url`;
4. старые варианты цены не хранить, кроме случаев, когда они прямо важны —
   тогда только в `price_note`.

Ключ уникальности продавца — `sellers[].id`. Он не меняется при обновлении
каталога, потому что на него завязаны URL сайта и ссылки в сообщениях
Telegram. При появлении username у продавца без контакта — обновить
`tg_kind`, `tg_handle`, `tg_url`, не меняя `id`.

Перед публикацией обязательно прогнать валидатор:

```bash
python3 tools/validate_catalog.py
```

Он проверяет уникальность `id`, ссылки на продавцов и категории, дубли по
ключу `(seller_id, normalized(name))`, согласованность
`price`/`price_unknown`, формат Telegram-ссылок, а также то, что `image`
указывает на существующий файл `.avif`.

## 5. Контакты продавцов и заказ в Telegram

Приоритет контакта:

1. **username** (`tg_kind: "user"` или `"group"`) — ссылка `tg_url`;
2. **канал** продавца, если он указан как основной контакт;
3. если username нет (`tg_kind: "message"`) — ссылка на сообщение-оффер в
   общем чате: `https://t.me/rus_nis/<messageId>`.

Пользовательских имён и телефонов, найденных в переписке, в каталог не
добавляем — только публичные Telegram-контакты.

### Формат заказа

На странице продавца у каждого товара есть кнопка «Заказать в Telegram».
Она:

1. собирает текст:

   ```
   Здравствуйте! Хочу заказать: <Название> — <цена> RSD / <unit>.
   Ссылка на товар: <URL страницы товара>
   Количество:
   Комментарий:
   ```

2. копирует его в буфер обмена;
3. для личного аккаунта (`tg_kind: "user"`) открывает
   `https://t.me/<username>?text=<urlencoded text>` — Telegram сам подставит
   текст в поле ввода;
4. для группы/канала или продавца без username открывает контакт и показывает
   тост «Текст заказа скопирован. Вставьте его в чат продавца» (Telegram не
   поддерживает предзаполнение текста для групп).

Ссылка на товар в сообщении имеет вид:

```
https://<домен>/#/seller/<seller_id>/<product_id>
```

По ней открывается страница продавца, нужная карточка подсвечивается.
Поэтому `seller_id` и `product_id` должны оставаться стабильными.

Кнопка в шапке продавца ведёт на контакт без текста заказа.

## 6. Устройство сайта

- `index.html` — каркас, шапка, футер, контейнер `#app`.
- `app.js` — загрузка `data/catalog.json`, поиск, фильтры, hash-роутинг,
  формирование Telegram-ссылок.
- `styles.css` — оформление, адаптив, бейдж «Цена не указана».
- `data/catalog.json` — единственный источник данных для сайта.

Маршруты (hash, без серверной маршрутизации):

- `#/` — все товары, поиск, фильтр по категориям;
- `#/seller/<seller_id>` — страница продавца;
- `#/seller/<seller_id>/<product_id>` — страница продавца с подсветкой товара.

Поиск ищет по названию, описанию, тегам, единице измерения, категории,
имени продавца и имени человека. Нормализация: регистр, `ё → е`, слова
ищутся по отдельности (AND).

Фото товаров хранятся в `data/images/products/<product-id>.avif` и выводятся
в карточках через поле `image`. Если фото нет — плейсхолдер: эмодзи категории
на фоне цвета продавца. Галереи нет: одна карточка = одно фото. **Все
изображения на сайте — AVIF**; JPG/PNG не подключаем.

Если несколько товаров ссылаются на один пост с одним фото, не ставим его
всем подряд: выбираем кадр, где виден именно этот товар (в альбомах фото
часто идёт следующим сообщением), иначе оставляем плейсхолдер.

## 7. Как добавить нового продавца или товар

1. Найти сообщения продавца в `data/messages.jsonl` (не старше периода из §1).
2. Убедиться, что это домашний продавец, а не кафе/магазин/рекомендация.
3. Добавить объект в `sellers` с новым уникальным `id` (латиница, дефисы).
4. Добавить товары в `products` с уникальными `id` вида
   `<seller-id>-<product-slug>`.
5. Проверить: цена в RSD, `unit`, `source_message_url`, `updated_at`.
6. Если в сообщении есть подходящее фото (`photos`), сконвертировать его в
   AVIF и добавить путь в `image`:
   ```bash
   python3 tools/import_image.py ChatExport_2026-11-25/photos/photo_…jpg <product-id>
   ```
   В каталоге появится `"image": "data/images/products/<product-id>.avif"`.
   В альбоме текст часто в первом сообщении, а нужный кадр — в следующих;
   проверяй глазами, что на фото именно этот товар.
7. Если цены нет — `price: null`, `price_unknown: true`.
8. Прогнать `python3 tools/validate_catalog.py` и открыть сайт локально.
9. Проверить: карточка есть в поиске, страница продавца открывается,
   кнопка «Заказать» ведёт в правильный Telegram, фото отображается.

При обновлении экспорта:

1. заменить папку экспорта;
2. перезапустить `tools/parse_export.py` (отсечка пересчитается от нового
   последнего сообщения);
3. обновить `catalog.json` вручную по свежим сообщениям;
4. обновить `updated_at` и `source.period_*`;
5. проверить дубли и ссылки.

## 8. Ограничения и осознанные решения

- Сайт статический, без бэкенда, корзины и оплаты. Заказ — в Telegram.
- Нет автогенерации каталога из сообщений: семантика (что считать товаром,
  как назвать, какая цена актуальна) требует ручного решения.
- Данные о наличии и ценах могут устареть — на сайте есть предупреждение
  «уточняйте у продавца».
- Фото товаров используются, но только в **AVIF**. Исходные JPG из экспорта
  не коммитим и не подключаем напрямую: конвертируем в AVIF (1200 px,
  quality 55) и кладём в `data/images/products/`.
- `ChatExport_2026-11-25/` исключён из git через `.gitignore`;
  `data/messages.jsonl` и `data/catalog.json` — рабочие данные проекта.
